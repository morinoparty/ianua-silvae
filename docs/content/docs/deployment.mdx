Ianua Silvae is designed to run permanently alongside your network, receiving traffic only when every real lobby is down. This page covers wiring it into Velocity and keeping it running with systemd.

## Register the server in Velocity

Add the server to `velocity.toml` and enable modern forwarding network-wide:

```toml
[servers]
lobby-1 = "127.0.0.1:25566"
lobby-2 = "127.0.0.1:25567"
ianua-silvae = "127.0.0.1:25580"

# ...

player-info-forwarding-mode = "modern"
```

The `forwarding.secret` file on the proxy must contain the same value as `velocitySecret` / `IANUA_VELOCITY_SECRET` on Ianua Silvae.

## Configure vlobby

Register Ianua Silvae **last** in vlobby's lobby list. With the `FIRST_AVAILABLE` strategy, vlobby connects players to the first reachable lobby in order — so the fallback only receives players when everything above it is down:

```yaml
strategy: FIRST_AVAILABLE
lobbies:
  - lobby-1
  - lobby-2
  - ianua-silvae   # fallback: keep this last
```

:::warning[Ordering matters]
If Ianua Silvae is listed before a real lobby, players will be routed to the fallback even while the main lobby is healthy. Always keep it at the end of the list.
:::

## Run as a systemd service

Ianua Silvae is a single jar, so a plain systemd unit is enough — no container required. Copy the release jar (e.g. `ianua-silvae-1.0.0.jar`) to `/opt/ianua-silvae/ianua-silvae.jar`:

```ini
[Unit]
Description=Ianua Silvae fallback lobby
After=network.target

[Service]
User=minecraft
WorkingDirectory=/opt/ianua-silvae
ExecStart=/usr/bin/java -Xms128M -Xmx512M -jar ianua-silvae.jar
Environment=IANUA_BIND=127.0.0.1
Environment=IANUA_PORT=25580
EnvironmentFile=/etc/ianua-silvae/secret.env
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

`/etc/ianua-silvae/secret.env` holds the forwarding secret outside the unit file:

```sh
IANUA_VELOCITY_SECRET=change-me
```

Enable and start:

```sh
sudo systemctl enable --now ianua-silvae
```

A small heap (`-Xmx512M`) is plenty: the server holds one schematic-based instance and, in normal operation, zero players.

## Run on Pelican Panel

If the fallback runs on a [Pelican Panel](https://pelican.dev/) server instead of systemd, import the egg at [`pelican/egg-ianua-silvae.yaml`](https://github.com/morinoparty/ianua-silvae/blob/main/pelican/egg-ianua-silvae.yaml). The egg:

- Downloads the requested (or latest) release jar from GitHub during install.
- Starts the server with `java -Xms128M ... -jar ianua-silvae-*.jar` — the jar keeps its versioned release name and the wildcard matches it, so no rename is needed on updates. Two startup commands are provided: ZGC (default) and G1.
- Offers the `ghcr.io/morinoparty/fruits` Java 25 images (Temurin, GraalVM, Azul Zulu, OpenJ9) as selectable docker images.
- Writes `bind` and the allocated port into `config/config.json`; the Velocity forwarding secret and MOTD are egg variables passed to the server as `IANUA_VELOCITY_SECRET` / `IANUA_MOTD` environment variables.
- Stops the server with SIGINT (`^C`) since the server registers no console commands.

### Automated deployment

When a GitHub release is published, the `deploy` job in `.github/workflows/upload.yml` runs `.github/scripts/pelican-deploy.sh`, which uses the panel's client API to:

1. Delete any existing `ianua-silvae*.jar` in the server root, so the wildcard startup command matches exactly one file.
2. Upload the freshly built `ianua-silvae-<version>.jar`.
3. Send a `restart` power signal to the server.

The job requires three repository secrets:

| Secret | Description |
| --- | --- |
| `PELICAN_PANEL_URL` | Panel base URL, e.g. `https://panel.example.com` |
| `PELICAN_SERVER_UUID` | UUID of the target server on the panel |
| `PELICAN_CLIENT_API_KEY` | Client API key (`pacc_...`) with file and power permissions |

## Operational notes

- **Keep it boring.** The fallback should have no scheduled restarts, no plugins to update, and no world to back up. Its only job is to be reachable when nothing else is.
- **Monitor reachability, not load.** Alert if the server stops answering pings; player count on it is itself a signal that the main lobby is down.
- **Test the failure path.** After any proxy change, stop the main lobby once and confirm players land in Ianua Silvae instead of being disconnected.
